# INFO-4. Quiet clinical-trial registry changes: pre-registration

Copied unchanged from research/infoedge/PREREG.md (written 2026-09-26, before any data was collected). The common rules in that file apply in full; the verdict bar is t >= 2.5 with the pre-registered sign in both halves.

## Spec (locked)

- **Why the market might not see it:** biotech companies update ClinicalTrials.gov records (primary completion date pushed back, enrollment cut, status changed to suspended, terminated or withdrawn), sometimes weeks before saying anything. The registry keeps a dated history of every version.
- **Events:**
  - trials sponsored by US-listed companies under $5B;
  - a record version that delays the primary completion date by 6 months or more, cuts target enrollment by 25% or more, or moves status to suspended, terminated or withdrawn;
  - no 8-K from the sponsor within 5 trading days before the version date.
  - Public date = the version date in the registry history + 1 trading day, or the posting date if the history distinguishes them.
- **Primary:** abnormal return over trading days +1 to +20. Expected sign: negative. Same bar.
- **Secondary:** Phase 2/3 trials only; companies under $1B.
- **Feasibility first:** confirm the record history, with its dates, can be retrieved for thousands of trials. If not, stop and say so.

Common rules that bind this test (from the shared file): point-in-time use from the first trading day after the public date; returns net of a size-and-industry benchmark (IWM under $2B / SPY otherwise if no benchmark can be built); Yahoo prices, with every company excluded for lack of prices recorded and the -30% / +15% bounds run for missing companies; results after 0.2% per event; t >= 2.5 and the expected sign in both halves for a Yes.

## Feasibility (checked 2026-09-26, before any return was computed)

- The public ClinicalTrials.gov API v2 serves current records only (its OpenAPI spec describes "the most recent version"); it has no history endpoint.
- The website's "History of Changes" tab is fed by two internal endpoints: `/api/int/studies/{NCT}?history=true` (every version: number, date, overall status, which modules changed) and `/api/int/studies/{NCT}/history/{v}` (the full record as it stood at version v). robots.txt explicitly allows `/api/int/` for all crawlers, with a 1-second crawl delay.
- A cookieless request to `/api/int/` gets 403. The endpoints answer once the client holds the site's ordinary `ncbi_sid` session cookie, which the server sets on any public request (for example the v2 API). The scripts here keep cookies like any HTTP client, send the project User-Agent, and do not impersonate a browser, solve a challenge, or forge anything.
- AACT (aact.ctti-clinicaltrials.org) needs an account for both cloud access and snapshot downloads; no account was created, and AACT holds daily snapshots, not version histories.
- Conclusion: dated version histories can be retrieved for thousands of trials without an account. The test proceeds.

## Deviations and implementation choices (fixed before any return was computed)

1. **Public date.** Each version record carries `lastUpdatePostDateStruct`, the date that version was posted, which is later than the date shown in the history list (the QC date). The history therefore distinguishes them, so, as the spec says, the public date is the posting date. Day +1 is the first trading day after the posting date; the window is trading days +1 to +20. If a version lacks a posting date, the fallback is the history date plus the 95th percentile of the observed QC-to-posting lag (reported in RESULTS.md).
2. **8-K window.** The spec says no 8-K within 5 trading days before the version date. Because the event is now dated at the (later) posting date, an 8-K filed between the version date and the posting date would also pre-empt the news, so the primary window runs from 5 trading days before the history version date through the posting date, inclusive. The literal window (5 trading days before the version date through the version date) is reported as a robustness line. Foreign private issuers file 6-K instead of 8-K; their 6-Ks count as 8-Ks.
3. **Change definitions.**
   - Delay: primary completion date later than in the previous version by 6 months or more (month arithmetic on the year-month; if both dates have a day and the gap is exactly 6 months, the new day must not be earlier).
   - Enrollment cut: target (estimated/anticipated) enrollment in the new version at most 75% of the target in the previous version. A switch from a target to an actual count (at completion or termination) is not a cut in target enrollment and is not counted; terminations are caught by the status rule.
   - Status: overall status changes to SUSPENDED, TERMINATED or WITHDRAWN from any other status.
   - Only versions posted from 2015-01-01 to 2026-08-26 (so that 20 trading days of returns exist).
4. **Unit of observation and t-statistic.** Several trials of one company often change on the same posting date and share one return window. Events are therefore one per company per posting date. The t-statistic is computed across these events, clustered by calendar month of the posting date (as in INFO-2). "Both halves" = events split at the median posting date.
5. **Sponsor mapping.** Lead sponsor only (collaborators ignored). Names matched to SEC registrants: current names from data/sec_cache/company_tickers.json plus every name used by a 10-K/10-Q/20-F/40-F filer in EDGAR's quarterly form indices 2014-2026 (so companies that have since been acquired or delisted are found). Matching on the normalised name (legal suffixes removed), or on the "core" name with generic industry words removed if that points to exactly one registrant and the registrant's SIC code is health care. 50 mapped names are checked by hand. The sponsor is the lead sponsor named in the version itself (point in time), not today's sponsor. A change is attributed to a registrant only if that registrant had filed a periodic report under a name matching the sponsor (same normalised name, or same distinctive core such as Sangamo BioSciences / Sangamo Therapeutics) by 120 days after the posting date, so a private company that later reverse-merged into a listed shell is not attributed to the shell's stock before the merger. Cost of this rule: the registry sometimes shows a company's later name in old versions, so a listed company that renamed itself to something unrelated (e.g. Onconova to Traws Pharma) loses its changes from before the rename.
6. **Size.** Market value at the posting date = the latest XBRL share count filed before that date (dei:EntityCommonStockSharesOutstanding where the company reports it, otherwise us-gaap/ifrs counts), put on today's split basis with Yahoo's split history, times the split-adjusted Yahoo close. Share counts more than 20 times the company's recent count, or below 1/1,000 of it, are treated as XBRL unit errors and dropped (for example BioNTech's first two 20-F covers, reported x1,000). If there is no usable share count, the latest public float (dei:EntityPublicFloat) stands in; companies with no Yahoo price use the float for the size screen. Foreign issuers (20-F/6-K filers) report ordinary shares while the US price is per depositary share (ADS): where Yahoo's current market value is below 1/1.5 of (latest XBRL shares x current price), that ratio is applied to all dates, and ordinary share counts are not re-based for Yahoo "splits" (which for ADSs are usually ratio changes). The same is done for one 10-K filer that trades as an ADS (BeiGene/BeOne, 1 ADS = 13 shares, checked by hand). A ratio above 1.5 is not applied, because for directly listed foreign companies it mostly reflects shares issued since the last XBRL count. Results excluding foreign issuers are reported as a robustness line.
7. **Benchmark.** Size-and-industry benchmark built from the study's own universe: industry group (drugs/biotech: SIC 2833-2836 and 8731; other health care) x size band (under $300M, $300M-$1B, $1B-$5B, $5B+, by market value at the previous month-end). The benchmark for an event is the average of the other cell members' own buy-and-hold returns over days +1 to +20 (members must trade on day +1), which avoids the rebalancing bias of compounding a daily equal-weighted average (Barber and Lyon 1997). If a cell has fewer than 10 members, IWM (under $2B) or SPY is used. Robustness lines: the daily-rebalanced version of the same benchmark, IWM/SPY alone and XBI alone. Because the peer set is built only from companies that still have Yahoo prices (survivor-built; INFO-5 found this makes small stocks look bad on any date), a placebo is also reported next to the headline: for each primary event, 5 random trading days (seeded) in the same calendar year for the same company, at least 20 trading days away from any of its events, same size rule and same benchmarks; reported are the placebo mean and the event-minus-placebo difference (per event: its abnormal return minus the mean of its own placebos), t clustered by month. (Benchmark choice and placebo were fixed on 2026-09-26 before any return was computed; the placebo and ETF-alone lines were requested by the coordinator after INFO-5 and do not change the verdict rule.)
8. **Missing companies.** An event is "missing" when the sponsor filed a 10-K, 10-Q, 20-F or 40-F in the 15 months before the posting date but Yahoo has no price for it. The -30% / +15% bounds are applied as the +1 to +20 abnormal return of every missing event.
9. **Prices.** Split- and dividend-adjusted daily closes from Yahoo. A daily return of -90% or worse followed the next day by +900% or more (or the reverse) is a bad print and both days are dropped; any remaining daily return above +1,000% is dropped.
10. **Trial set and download.** Histories are downloaded for every industry-sponsored interventional trial updated since 2015 whose current lead sponsor maps to a company that passes a loose size screen (a month-end market value or a reported public float under $5B at some point since 2015, or no size data at all); the exact screen is applied per event. Consequence: a trial now sponsored by a large company but earlier by a small one it acquired is not downloaded. Downloaded per trial: the version list, the last version dated before 2014-12-01 (baseline) and every version dated 2014-12-01 to 2026-08-26 that changed the Status or Design section. The download is slow (about 11 requests per trial, at most 2.9 requests a second), so trials of companies that have Yahoo prices are downloaded first, all of them, and the others (which only feed the missing-company bounds) afterwards; order is random (seeded) within each group. If the second group is not complete when the first is, the number of missing-company events is scaled up from the random fraction downloaded, and the scaling is reported.
