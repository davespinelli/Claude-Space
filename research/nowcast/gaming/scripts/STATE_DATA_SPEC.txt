STATE MONTHLY CASINO REVENUE: COMMON OUTPUT SPEC (for scripts/state_<st>.py)
===========================================================================

Project root: /Users/davidspinelli/Documents/Claude Space/research/nowcast/gaming
Context: a pre-registered research pilot (PREREG.md) nowcasts listed casino operators'
quarterly revenue from state regulators' monthly casino revenue, property by property.

Files each state produces (st = two-letter lowercase state code):
  scripts/state_<st>.py     downloader + parser; re-runnable; raw files cached, never re-downloaded
                            if already in cache. Module docstring documents: sources (URLs),
                            measure used, month range, publication-date method, quirks,
                            spot-check results.
  cache/<st>/               raw downloads (PDF/XLS/HTML...). Never commit (cache/.gitignore = *).
  data/state_<st>.csv.gz    cleaned monthly panel (schema below).
  data/state_<st>_checks.csv.gz   spot checks: month, sum_of_units, regulator_total, diff_pct, note.

Schema of data/state_<st>.csv.gz (one row per unit per month):
  state          two-letter upper case, e.g. PA
  unit           property (or region/town/area) name exactly as the regulator publishes it,
                 whitespace-normalised. If the regulator renames a property over time keep the
                 name used in each month's report (the mapping to owners is done later), BUT add
                 a stable id in unit_id.
  unit_id        stable identifier for the same physical casino across renames within the state,
                 e.g. "PA_PENN_NATIONAL" (your best judgement; keep a small hand-coded rename map
                 in the script; say in the docstring which renames you linked).
  unit_level     property | operator | region | town | county | area | state_total
  month          YYYY-MM
  ggr            land-based casino gaming revenue for the month in US dollars (float, not
                 thousands): slots + table games (+ poker) using the state's primary measure
                 (GGR / AGR / gross win / net terminal income for VLTs). EXCLUDE sports wagering,
                 online/iGaming, fantasy, lottery, pari-mutuel, truck-stop VGTs, distributed/route
                 gaming. Mini/satellite casinos are separate units.
  slots          slot/VLT component if published, else blank
  tables         table-games component (incl. poker) if published, else blank
  n_casinos      for region/town/area/county rows: number of casinos reporting, if published
  measure        short label of the measure (e.g. "GGR", "AGR", "NTI", "casino win")
  pub_date       YYYY-MM-DD date the month's report was first published, if findable
                 (press-release date, report date printed in the document, PDF CreationDate
                 metadata, dated news listing). Blank if unknown. Do NOT use HTTP Last-Modified of
                 re-uploaded archives unless nothing else exists; say which method in pub_source.
  pub_source     press_release | report_text | pdf_metadata | listing_page | http_last_modified | ''
  source_file    cache-relative file name the row came from

Also include one row per month with unit="__STATE_TOTAL__", unit_level="state_total", ggr=the
regulator's own published statewide total for the same measure (if published), so totals can be
checked. If the regulator only publishes region/area rows, still include the state total.

Coverage wanted: every month from 2012-01 (or the earliest available after that) through the latest
month published (probably 2026-07 or 2026-08). Breadth of years matters more than extra columns.
Weekly data: aggregate to calendar months pro-rata by days and say so in the docstring.
Fiscal-year Excel files: map to calendar months carefully.

Quality bar:
  * Spot-check sum-of-units vs the regulator's statewide total for at least 8 months spread
    across the years (all months if cheap); investigate any |diff| > 1%.
  * Check units (dollars vs thousands) and scan each unit's series for impossible jumps
    (e.g. month/month ratio > 3x or < 1/3 outside Mar-Jun 2020 COVID closures, or a sudden
    1000x). Fix parse errors; document real ones (openings, closures, renames).
  * No duplicate (unit_id, month) rows.
  * COVID closures: months with zero revenue should be 0, not missing.
