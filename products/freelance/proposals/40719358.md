## Proposal

If the numbers already live in an online database, retyping them is the slowest and least accurate way to move them. The real risk is a partial copy: a filter or a paging limit quietly drops a block of records, and the finished sheet cannot show you what is missing. So I pull the records through an export or a read-only query and reconcile row counts and totals against the source.

Plan:
- Confirm which records are in scope and whether an export or read-only access exists.
- Extract them, then check row counts and column totals against the database before touching the sheet.
- Build the spreadsheet with typed numbers, one format per column, and a source note on every field.
- Repeat the pull as a script if this recurs, so the next run costs nothing.
- Handle the copy separately, once I know what it is for and how long.

You receive the spreadsheet, the reconciliation figures, and the extract script if access allows.

Proof: my public repo and live data pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: can I get an export or read-only access to the database, and what copy do you need written?
