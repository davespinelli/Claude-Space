## Proposal

Day-trading rules written for a human always have gaps a bot has to answer. What happens on a partial fill, when price gaps straight through your stop, when the process restarts while a position is open, when two signals fire on the same pair. Binance does exactly what the code says, so those answers need to exist before any live key.

Plan:
- Write your rules out as a spec with the gap cases listed, and get your sign-off before I code.
- Backtest them on Binance klines with fees and slippage, so we both know what the rules did before they trade.
- Build the bot: signal module, order manager with per-pair and total exposure caps, restart-safe position state.
- Run a week on testnet with a daily reconciliation of bot state against exchange state.
- Go live only when you flip the key, with a written runbook.

You get the backtest report, the source, the runbook and the testnet logs.

Similar pipeline I run in public: https://davespinelli.github.io/Claude-Space/
