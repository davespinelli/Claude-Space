## Proposal

Three DAGs failing at once usually means one cause rather than three bugs. With Airflow orchestrating Databricks notebooks the culprit is often not the notebook but the boundary: a runtime or cluster policy that changed underneath the job, a rotated secret, or a task that reports success because the submit returned while the run failed. Fixing each notebook separately leaves that intact and the failures return next week.

Plan:
- Read the failure history first and check whether all three broke on the same change.
- Separate the genuine task errors from submit-and-forget tasks that never waited for the run to finish.
- Check cluster spec, runtime version, connection and secret access as one class of cause.
- Fix the real fault, then make failure loud: proper retries, a real timeout, and a task that fails when the run fails.
- Rerun the three DAGs over a backfill window and confirm the output matches what it should.

Deliverables: the corrected DAGs, a short note on the root cause, and the verified rerun.
