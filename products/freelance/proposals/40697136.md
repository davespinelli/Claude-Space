## Proposal

Descriptive statistics for a publication have a specific failure mode: the tables are made by hand from one version of the sheet, then the data gets a correction, and the manuscript no longer matches the data behind it. So I build the tables from a script that reads your sheet, which makes a data revision a re-run rather than a rebuild.

Plan:
- Check the sheet first for the things that quietly change results: text stored as numbers, missing values coded several ways, duplicate records.
- Agree how missing data is handled and reported, since that choice is yours and has to be stated in the paper.
- Produce the standard descriptives: n, mean, standard deviation, median and range for continuous variables, counts and percentages for categorical ones, split by group if needed.
- Format the tables to your target journal's layout.
- Send the script with the tables so you can re-run it after any data correction.

You receive the tables, the script, and a short note on the decisions made.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: how many variables and cases, and which journal or style guide are the tables for?
