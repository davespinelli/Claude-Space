## Proposal

Romanian company data has one thing going for it: the CUI. Every record ties back to it, and a build that matches on company name instead will duplicate firms and miss the ones that changed trade name last year. The second question is which source you mean, because the registry record and the fiscal record do not carry the same fields, and picking late means scraping twice.

Plan:
- Agree the source and the exact field list before any code is written.
- Key every record on the CUI, so a rerun updates a company rather than adding a second copy.
- Normalise name, address, county, activity code and status into one consistent table.
- Export to CSV or Excel with the pull date on every row, plus counts of new and changed.
- Make it rerunnable on a schedule, with the source and a README you can hand to anyone.

You get the scraper, the database export and the source.

Pipeline I run in public: https://davespinelli.github.io/Claude-Space/

To be straight: public company records only, nothing behind a login and no personal contact details.

Two questions: which source should be the base, and which filters define the set you need?
