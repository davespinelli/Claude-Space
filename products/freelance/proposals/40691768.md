## Proposal

You have a set of PDFs that has to end up as one clean, well structured Excel file. The hard part is rarely reading the pages. It is that the layout drifts between documents: a table that breaks across a page, a cell that wraps onto two lines, a subtotal row that looks like data. Typing it once solves today and leaves you doing it again next month.

Plan:
- Review two or three sample PDFs with you and agree the exact columns and what one row represents.
- Write a Python extractor that handles page breaks, wrapped cells and repeated headers.
- Normalise types so the sheet actually sorts and filters: dates, numbers, currency, stray spaces.
- Run a check pass comparing row counts and totals per file against the source, recorded in a QA tab.
- Deliver the workbook plus the script so you can rerun it on the next batch yourself.

You receive the finished Excel file, the extraction script with a README, and a short note on any page that needed a judgement call.

Public example of my pipeline work: https://github.com/davespinelli/Claude-Space

Two questions: how many PDFs are in the set, and are they text based or scanned images?
