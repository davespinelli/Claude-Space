## Proposal

User management is where a Flask app either stays safe or quietly stops being safe. The parts that get skipped under time pressure are the ones that matter later: password hashing that is actually slow, sessions that expire and rotate on login, roles checked on the server rather than hidden in the template, and a reset flow whose token is single use and short lived. Bolting those on after launch means touching every route again.

Plan:
- Set up Flask with blueprints, SQLAlchemy models and migrations, so the schema can change without hand edits.
- Build registration, login, password reset and role based access, with checks enforced in the route layer.
- Add an admin view to list, search, deactivate and change roles on users.
- Build the analytics page from real queries on your data, with the numbers you name rather than generic counters.
- Ship with tests on the auth paths, a seed script and deployment notes.

You get the app, tests, migrations and a README.
