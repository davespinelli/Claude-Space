## Proposal

The thing that sinks a reporting agent is not that it fails. It is that it answers confidently with the wrong number. A model writing SOQL will happily return a figure that looks plausible while counting the wrong records, filtering on the wrong owner, or silently truncating at the page limit, and nobody downstream can tell. So the agent should show its working: every answer carries the query it ran and the record count behind it, and the connection is read-only so a bad query can never write.

Plan:
- Read-only connected app with a scoped user, so the agent cannot modify Salesforce.
- Vetted query templates for your common questions, generated SOQL only for the rest.
- A join layer that merges Salesforce records with your platform's own data.
- A FastAPI endpoint returning the answer, the query, and the row count together.
- An evaluation set of about thirty questions with known answers, and the measured accuracy reported.

You get the service, the eval set with its scores, and the source.
