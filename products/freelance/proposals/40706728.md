## Proposal

Fifty pages of text-based PDFs is the good case. The text layer is already there, so this is extraction and verification rather than retyping, and the accuracy risk moves off the keyboard and onto the table structure. The things that break it are specific: rows that wrap onto a second line, cells merged across columns, headers repeated at every page break, and subtotal rows sitting in the same columns as the values they summarise.

Plan:
- Pull the text layer page by page and confirm every page has one, so nothing is silently missed.
- Extract each table with the column boundaries checked against the page rather than guessed.
- Rejoin wrapped rows, drop repeated page headers, and keep subtotal rows marked rather than mixed in with data.
- Tie out each numeric column against the totals printed on the page and tell you where they disagree.
- Deliver typed columns, with a page number on every row so any value traces back.

You get the XLSX workbook, the tie-out check, and a list of anything the original left ambiguous.
