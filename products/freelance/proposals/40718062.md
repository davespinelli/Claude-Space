## Proposal

An AI service for finance companies fails in a particular way: the same document run twice gives two different answers, and the client notices it before you do. The causes are a short list, usually sampling left switched on, prompt context that varies between runs, retrieval returning chunks in a different order, and no check that the output actually matches the source.

Plan:
- Build a regression set first, twenty real documents with the answers you consider correct, so the problem becomes measurable instead of anecdotal.
- Run each one five times and measure where output diverges, field by field rather than as a whole response.
- Fix the mechanical causes: temperature and seed, stable chunk ordering, and a strict output schema so fields cannot drift shape.
- Add a validation pass that checks each extracted figure back against the source text and flags anything it cannot find.
- Re-run the regression set and give you the before and after numbers.

You receive the fixes, the regression harness so you can run it on every future change, and a written account of what was causing what.

Proof: my public repo and live daily pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: which model and framework is it running on today, and can you share a few documents where the inconsistency shows?
