## Proposal

The totals are the part that has to be trustworthy, and hand-keyed numbers hide their own errors inside them. A transposed digit in one row moves the total by an amount nobody can spot, because there is nothing to check the total against except the typing that produced it. So the useful deliverable is not a filled sheet, it is a filled sheet where every total traces back to the source figures it came from.

Plan:
- Extract the numbers from your source files rather than retyping them, so the sheet matches the source by construction.
- Build the Excel workbook with a raw sheet, a labelled working sheet and live total formulas.
- Reconcile: row counts and control sums checked against each source file, differences listed.
- Flag anything ambiguous into an exceptions tab instead of guessing at it.
- Rerunnable, so next month's files go through the same path.

You get the workbook, the reconciliation report, the extraction script and the source.

Pipeline I run in public: https://davespinelli.github.io/Claude-Space/

Two questions: what format are the source files in, and which totals do you need, column sums only or subtotals by category and period as well?
