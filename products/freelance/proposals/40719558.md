## Proposal

An agent that places real orders has one failure mode that decides whether it is usable, and it is not the signal. If the process restarts mid session and re-sends a signal it already acted on, you get a doubled position, and no amount of strategy quality fixes that afterwards. So I build the order layer first: one client order id per signal, and a reconciliation against the broker's own positions on every start.

Plan:
- Write your entry, exit and sizing rules down as testable conditions before any code.
- Backtest them with costs and next-bar fills, so the agent has a measured baseline rather than a hope.
- Build execution on your broker's API with position caps, a daily loss limit and a kill switch.
- Run one week on paper, reconciling fills and positions against the log each day.
- Schedule it so it runs without your machine being on.

You receive the strategy code, the backtest report, the bot, and a runbook.

Proof: my backtest engine, Alpaca bot and live daily pipeline at https://davespinelli.github.io/Claude-Space/
