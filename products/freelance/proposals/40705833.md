## Proposal

Most AI CRM MVPs stall on the API side rather than the model side. The CRM has required fields, per minute rate limits and its own duplicate rules, and a model's free text output respects none of them, so the first integration either writes malformed records or gets rejected and drops the lead without anyone noticing.

Plan:
- Ship one workflow end to end first, with you naming the trigger and the record it should produce.
- Write a typed schema for that record, validate every model output against it, and reject rather than write on a mismatch.
- Wrap the CRM client with retries, rate limit handling and a duplicate check before insert.
- Log every attempt with input, model output and CRM response, so a bad record can be traced in one step.
- Run against a sandbox or test account before it touches live data.

You get the working automation, the schema and validation layer, the run log, and a README for adding the next workflow yourself.

A pipeline I run publicly on GitHub Actions: https://davespinelli.github.io/Claude-Space/
