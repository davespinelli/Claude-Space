## Proposal

A formatting problem sitting downstream of a model call is usually not a formatting problem. The model returns markdown or prose that varies from one run to the next, the page renders whatever arrives, and the instinct is to patch the display until the next response comes back a different shape. The fix that holds is to constrain the output: ask for a defined structure, validate it on arrival, and render from fields rather than from free text.

Plan:
- Reproduce the broken output first and capture the raw response, not the rendered version.
- Pin the model call with a defined JSON schema, validation on the response, and a retry when validation fails.
- Render from the validated fields so the page cannot receive a shape it does not handle.
- Cover the failure path, so a timeout or a refusal shows something sane instead of a blank panel.
- Leave the change in your codebase with a short note on what moved and why.

You get the working feature, the changed files and that note.
