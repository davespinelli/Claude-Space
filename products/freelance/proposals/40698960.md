## Proposal

Store isolation and permission bugs are not found by reading code. They are found by taking a low privilege account and deliberately asking for another store's data, then seeing whether the server refuses or the front end simply hides the button. That distinction is the whole audit, and it is the one an internal team is least placed to make.

Plan:
- Map the roles and the data boundaries first, then test each boundary directly against the API rather than through the UI.
- Check authorisation on every endpoint, including the ones the interface never calls.
- Review the migration history for irreversible or unordered steps, and the deployment path for secrets and defaults.
- Exercise QR and loyalty flows for replay, reuse and value tampering.
- Check the RTL interface for real layout and input failures, not just mirrored text.

You receive a written report: each finding with reproduction steps, severity, evidence, and a suggested fix, ordered by what to do first. Review only, no production changes.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
