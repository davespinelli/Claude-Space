## Proposal

Two files reconcile cleanly only when both sides carry a key that means the same thing. Usually one side has a reference number and the other does not, so the match falls back on name and date, which produces false matches that look like agreement. A reconciliation can read ninety percent matched and still be wrong.

Plan:
- Look at both files first and agree the match key, plus the tolerance for amounts and for dates.
- Prepare the first file: consistent types, trimmed text, dates parsed, numbers as numbers, so formatting does not defeat the match.
- Match in passes: exact key, then key within tolerance, then name and date, labelling how every row matched.
- Deliver the exceptions as the real output: unmatched on each side and rows where amounts differ, with the gap shown.
- Keep it repeatable so next period is a re-run on the new files.

I work on copies downloaded from SharePoint unless you want it run in place, which needs access your side.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many rows on each side, and is there a shared reference number between the two files?
