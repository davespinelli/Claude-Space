## Proposal

Your title covers four jobs that fail for different reasons, and reporting is usually the one that stalls. The Neurons console reports what Ivanti decided to report, which is rarely the patch compliance view management actually asks for, so the numbers get rebuilt by hand in Excel every month and drift from the console within a week.

Plan:
- Pull device, patch and compliance data from your Neurons tenant over its REST API on a schedule.
- Store each pull with its timestamp so month-on-month movement is a query, not a memory.
- Automation scripts for the repeating actions you name: reboot chasing, failed-patch retries, group membership.
- Dashboard: compliance by group, patch age, failures with reasons, devices not reporting in.
- Deploy on a schedule with a README and handover call.

You get the API layer, the automation scripts, the dashboard and the source.

Dashboard I run in public: https://davespinelli.github.io/Claude-Space/

Straight answer on scope: I build the API, automation and reporting layer in Python. I am not a licensed Neurons administrator, so in-console patch policy configuration is not mine.

Two questions: do you already have a Neurons tenant with API credentials, and do you need the in-console setup done too or only the automation and reporting on top?
