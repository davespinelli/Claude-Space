## Proposal

A busy shared mailbox is not hard to route, it is hard to route safely. Roughly one message in ten does not fit any of the categories you had in mind when the rules were written, and a flow that forces those into a bucket loses them quietly. The design question is what happens to the ones the rules cannot classify.

Plan:
- Map the real traffic first: sample a week of mail and count what actually arrives, before writing a single rule.
- Build the flow so every message is classified, assigned and logged as a task, with the mail linked back.
- Send anything below the confidence line to an unsorted queue that a person clears, rather than a guessed category.
- Surface the queue on a dashboard showing open tasks, owner and age, so nothing sits unseen.
- Add a run log, so a failed flow is visible instead of silent.

You receive the flows, the task list, the dashboard and a short note on editing the rules.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: how many messages a day, and where should tasks live, Planner, a SharePoint list, or somewhere else?
