## Proposal

You want a dashboard that reads live from your API rather than from an exported file. The usual problem with that is not the charts, it is the API layer: rate limits, paging, a field that is null on some records, and the moment the endpoint is slow the whole page hangs or shows stale numbers with no warning.

Plan:
- Map your endpoints, auth and paging, and agree which metrics come from which fields.
- Build a small fetch layer with retries, a short local cache and a visible last-updated timestamp.
- Render the views: headline figures, a trend chart, and one breakdown table with filters.
- Handle the failure cases explicitly so a bad response shows an error, not a wrong number.
- Deliver the source with a README covering config and how to add a metric.

You receive the running dashboard, the code, and setup instructions.

Live example of a dashboard I run: https://davespinelli.github.io/Claude-Space/

Two questions: can you share the API docs or a sample response, and do you want this hosted or run on your own machine?
