## Proposal

Automatic reply tools usually work on the clean case and struggle everywhere else: a thread with three prior messages quoted underneath, a reply that needs one fact from an earlier email, an attachment the sender assumes you read. The model is rarely the weak part. What it gets handed is. Trimming quoted history, passing the whole thread, and adding the few account details it needs will change the output more than swapping models.

Plan:
- Read the current code and list where replies actually go wrong, with examples from your own inbox.
- Fix the input first: thread assembly, signature and quote stripping, sender context.
- Tighten the prompt into a fixed structure with a house tone, and keep it in one editable file.
- Add a review step in the dashboard so a person can edit before sending, with the edit logged.
- Track the numbers that matter: share sent unedited, average edit size, failures.

You get the updated dashboard, the prompt file, and a short note on what changed and why.

A dashboard I run publicly: https://davespinelli.github.io/Claude-Space/

Two questions: what is the current stack and model, and can you share ten replies you were not happy with?
