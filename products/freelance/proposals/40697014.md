## Proposal

Clio Grow intake automation usually goes wrong in two places: the same person arrives twice through different channels and becomes two contacts, and a half-finished intake creates a matter that sits in the pipeline as if it were real. Both are cheap to prevent at the point of write and expensive to clean up later.

Plan:
- Map your intake first: where enquiries come in, which fields you capture, and what a complete intake means to your firm.
- Build the write path against Clio's API rather than the browser, so it survives interface changes.
- Match before creating: check for an existing contact or matter by email and phone, then update instead of duplicating.
- Create a matter only when the intake meets the completeness rule we agree, and hold the rest in a review queue.
- Log every write with a timestamp and source record, so any entry in Clio traces back.

You receive the running automation, the source, a mapping document and a runbook.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
