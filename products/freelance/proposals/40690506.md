## Proposal

A repeating Excel to MySQL import lives or dies on what happens the second time you run it. If the same workbook is loaded twice you get duplicate rows, and if one sheet has a bad date the whole batch can land half written. Both are fixable, but only if the import is designed for them up front.

Plan:
- Read each workbook with pandas, map sheets and columns to your tables through a config file rather than hardcoded names.
- Validate types and required fields before any write, and reject a file with a clear reason rather than importing part of it.
- Load inside a transaction with an upsert key, so a rerun updates instead of duplicating.
- Log every run: file name, rows read, rows inserted, rows updated, rows rejected.
- Schedule it on cron or Task Scheduler, with a non zero exit code so failures are visible.

You receive the import tool, config, logs and a README with the schedule setup.

Public example of my automation running on a schedule: https://github.com/davespinelli/Claude-Space
