## Proposal

A case sensitive text captcha does stop the scripted signups and form spam that make up most of the noise, but only if the answer is checked on the server. If the expected string is anywhere in the page or in the JSON the browser receives, a bot skips the whole thing in one line, and plenty of drop-in captchas do exactly that. So the design point here is where the answer lives.

Plan:
- Generate the challenge server side: random mixed case string, distorted render, answer held in a signed short lived token that the browser never sees.
- Compare case sensitively, one attempt per challenge, fresh image on every reload and after every failure.
- Rate limit by IP and session so the same client cannot grind attempts.
- Ship it as a drop-in: one HTML snippet for the form and one validation call in your backend.
- Add a simple accessibility fallback so real users are not locked out.

You receive the widget, the server endpoint, integration notes and the source.
