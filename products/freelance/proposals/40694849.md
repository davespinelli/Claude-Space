## Proposal

Your brief asks for three things that usually get built as three disconnected pieces: a set of pages, an analysis, and a model. The join is where these go wrong. The analysis ends up as charts pasted into the HTML, and they are stale the first time the data changes, so someone has to redo the work by hand every month.

Plan:
- Agree the dataset, where it comes from, and how often it needs to refresh.
- Write the analysis as a script that regenerates every number and chart on the site, so a rerun updates the pages instead of a manual edit.
- Train the model with an honest holdout split, report the accuracy plainly, and tell you if it is not good enough to put in front of users.
- Put the model behind a small endpoint the pages call, with input validation and a sane response when it fails.
- Build the pages against that, check them on mobile, deploy where you want them.

You receive the site, the analysis and training scripts, the trained model with its evaluation numbers, and a README so you can rerun the whole thing yourself.

Proof: my public repo and the live dashboard it builds at https://davespinelli.github.io/Claude-Space/

Two questions: what is the dataset and what should the model predict, and where should the site be hosted?

David
