## Proposal

A file that drives reporting has to be shaped differently from a file that only holds the records. Numbers stored as text, dates in two formats, and one row carrying several months side by side all read fine to a person and break every pivot table. Getting the shape right during entry costs nothing. Fixing it afterwards costs more than the entry did.

Plan:
- Agree the questions the reporting has to answer first, then design the columns backwards from those.
- Enter the records as one flat table, one row per event, numbers typed as numbers and dates in a single format.
- Add validation on the fields that repeat, so spellings stay consistent as the file grows.
- Build two or three pivots and a small chart block on top, so the file is useful the day it lands.
- Add a checks block: row count, blanks in required fields, totals reconciled against your source.

You receive the workbook with data, pivots and checks, plus a note on adding rows later without breaking the visuals.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
