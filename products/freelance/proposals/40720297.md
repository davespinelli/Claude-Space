## Proposal

On a platform that matches users to content, accuracy is not one number. A bad match can come from content tagged wrong, a profile built on stale signals, or a ranking step that quietly prefers popular items to relevant ones. Those have different fixes, and until they are separated any change is a guess that happens to feel better.

Plan:
- Build a small evaluation set first: a few hundred user and content pairs judged good or bad, so a change can be measured rather than argued.
- Score the current pipeline against it and split the errors by cause: tagging, profile, ranking.
- Fix the largest cause first, rather than replacing a pipeline that is mostly working.
- Rerun the evaluation after each change and report the delta honestly, including anything that got worse.
- Leave the evaluation as a script you run on every future change, so this does not recur.

Deliverables: the evaluation set and harness, a short report of error causes with numbers, and the pipeline changes themselves.
