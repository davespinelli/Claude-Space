## Proposal

With the sensors already publishing, the dashboard is the easy half. The half that decides whether you trust it is what happens when a probe goes quiet. A Node-RED gauge holds its last value indefinitely, so a dead EC probe and a genuinely stable reading look identical on screen. Stale detection per topic is the thing to build in from the start, not to add after it has misled you once.

Plan:
- Map your topics and payload shapes, one sample message per sensor.
- Build the dashboard: live gauges, a chart per sensor group, and a status tile per device.
- Mark any reading older than a threshold you set as stale, instead of showing it as current.
- Log readings to a local store so the charts survive a Node-RED restart.
- Add alerts on stale topics and on out of range values, to email or Telegram.

You receive the flow export, the dashboard, the alert rules and a README on adding a sensor later.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
