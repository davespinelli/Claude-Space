## Proposal

Wiring a form to a database is the easy half. The half that decides whether this holds up is what happens on a bad submission: a blank required field, a number typed with a currency symbol, the same entry sent twice because the first attempt looked slow. Without that handled, the database fills with rows nobody trusts and the workbook stays the real record.

Plan:
- Agree the target table and the type of every field, so text and numeric inputs land as the right column types rather than all as text.
- Validate in the workbook before anything is sent, and refuse the submission with a plain message when a field is wrong.
- Write through a parameterised insert with a submission id, so a repeated click updates rather than duplicates.
- Log every submission locally with its result, so a failed send is visible and can be retried rather than lost.
- Connect with a restricted account, credentials kept outside the workbook file.

You receive the wired workbook, the table definition, the insert and retry code, and setup notes.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
