## Proposal

Talking to a prop firm's API is the easy half. The part that costs people an evaluation is what happens when the session drops mid position, or an order comes back rejected and the script carries on as if it filled. Prop rules are unforgiving about exactly that, so I build the connection and risk layer first and hang the signals off it.

Plan:
- Read the firm's API docs and confirm auth, order types, rate limits and what a rejection looks like before writing anything.
- Build the connection layer with reconnect and position reconciliation, so a dropped session cannot leave an unknown position open.
- Wire your entry and exit rules in as a separate module, so the strategy can change without touching the plumbing.
- Add hard caps: max position size, daily loss stop, flat by time.
- Run it on the demo or evaluation account and log every order and fill to CSV so you can audit any day.

At this budget the price covers the connector, the risk caps and one rule set running on a demo account. Anything beyond that we scope as a second milestone.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
