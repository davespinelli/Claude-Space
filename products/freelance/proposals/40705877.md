## Proposal

A prompt audit is only worth paying for if the changes are measured. Without a fixed set of real conversations to score against, rewriting a prompt swaps one set of untested wording for another, and the failures that prompted the audit come back a month later wearing a different shape.

Plan:
- Collect fifty to a hundred real conversations, the bad ones included, and freeze them as a test set.
- Score the current prompt against that set on your criteria, so there is a baseline number before anything changes.
- Read the prompt for the usual failure sources: conflicting instructions, missing refusal paths, vague tool descriptions, unbounded context.
- Rewrite in numbered passes, rescoring the same set after each, keeping only changes that move the score.
- Hand over the test harness so your team can rerun it on every future edit.

You get the rewritten prompt, the scored before and after, the test set, and a short note on each change and why it survived.

Public repo with a live CI pipeline: https://davespinelli.github.io/Claude-Space/

## Delivery plan
1. Day 1: agree the scoring criteria and pull the transcript sample.
2. Day 2: build the test harness, score the current prompt, report the baseline.
3. Day 3 to 4: first rewrite pass and rescore, with the diff and score change written up.
4. Day 5 to 6: second pass on whatever the scores still show failing, plus refusal and edge cases.
5. Day 7: final prompt, harness handover, written note per change.
