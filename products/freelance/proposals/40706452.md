## Proposal

Ongoing work that moves between a web source and a spreadsheet fails in a predictable place. After a few weeks nobody can say which rows were entered from which page, or when, so a disputed value cannot be traced back and the only fix is to redo the batch. That is a column problem, and it costs nothing to solve on day one.

Plan:
- Set the sheet up first: one column per field, types fixed so codes keep leading zeros and dates stay dates.
- Add a source column and an entered-on column, so every row points back at the page it came from.
- Enter the first batch, then reread it against the source rather than against my own typing.
- Flag anything the source leaves ambiguous in a queries tab instead of guessing at it.
- Send you the batch with a short count of rows entered, rows queried and anything the source was missing.

You get the completed sheet, the queries tab and a one-page note on how the columns are set up so later batches stay consistent.

How I work in public: https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many rows per week, and is the web source a public page or something behind a login?
