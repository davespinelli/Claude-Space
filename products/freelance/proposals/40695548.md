## Proposal

Your source is a well structured online database, which changes the job. Typing those records into Excel by hand introduces errors that were not in the source, and it cannot be repeated next month without paying for it again. I would read the records out programmatically and validate them, so the workbook matches the database exactly and can be regenerated on demand.

Plan:
- Agree the export route: an existing export, an API, or a read only view of the database.
- Pull the records and load them into your workbook layout, preserving text as text and numbers as numbers so nothing is silently reformatted.
- Run validation on every row: required fields, type checks, date parsing, duplicates, and values outside the ranges you expect.
- Deliver an exceptions sheet listing anything that failed a check with the reason, rather than quietly correcting it.
- Give you the script so the next refresh is a re-run, not a re-order.

You receive the completed workbook, the exceptions sheet, the script, and a short README.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many records, and can you export from the database or do I work from screens?

David
