## Proposal

A claims engine is a rules problem wearing an API costume. The endpoints are the easy half. The hard half is that a claim gets decided, then adjusted, then reprocessed under rules that changed last month, and you have to be able to say later why that decision came out the way it did.

Plan:
- Model the claim as a state machine with an append-only decision log, so every status change records the rule version and the inputs that produced it.
- Keep the rules in versioned, testable form rather than buried in endpoint code, so a rule change is a reviewable diff.
- Build the API in FastAPI with typed request and response schemas and idempotent submission, so a retried claim does not double process.
- Cover the rules with tests case by case, including the edge cases you already know are painful.
- Ship with an OpenAPI spec, migrations and a runbook.

Price covers a first release: submission, validation, rules evaluation, status and history endpoints.
