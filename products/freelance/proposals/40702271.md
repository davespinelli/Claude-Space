## Proposal

The phrase that decides this job is "various tasks". An assistant that is pointed at everything ends up trusted with nothing, because the first time it does something wrong unattended you have to check all of its output by hand from then on. The ones that survive start with two or three named tasks and earn their way outward.

Plan:
- Pick the two or three tasks that cost you the most time each week and automate those first.
- Give the assistant real tools for them rather than free-form output: read a file, call an API, write a row, send a draft.
- Log every action it takes, so you can see what it did and why.
- Keep anything irreversible behind your confirmation until it has run clean for a week.
- Hand over the code and a README so you can add the next task yourself.

You get the working assistant, the logs and the handover notes.

Proof of my automation work: https://davespinelli.github.io/Claude-Space/
