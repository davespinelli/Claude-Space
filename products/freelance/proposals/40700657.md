## Proposal

The part that hurts with a desktop form filler is not the typing, it is the restart. The run stops on row 400, nobody knows whether row 400 went in, and the safe move is to redo the batch and risk duplicates.

Plan:
- Read the CSV or Excel source and validate every row before anything is typed, holding back failures with a reason.
- Drive the form the way it expects, field order and keyboard, waiting on each screen rather than on a fixed timer.
- Write a progress file after each row, so a stopped run resumes at the next unsent row.
- Log every submission with source row number and result, so you can prove what was entered.
- Add a dry run mode that fills the form and stops before submit, for your first pass.

You get the utility as a Windows executable, the config file, the run log and a setup note.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
