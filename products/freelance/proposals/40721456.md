## Proposal

Two small tasks together, both time sensitive, and one of them in Hindi. The risk in Hindi sheet work is not typing speed, it is encoding. Devanagari entered in a legacy font like Kruti Dev looks correct on the machine that typed it and turns into unreadable characters as soon as the file moves, gets sorted, or is opened in Sheets. I work in Unicode throughout and confirm the file opens clean elsewhere before it comes back.

Plan:
- Confirm the source first: digital text I can read from, or scans, or handwriting.
- Set the sheet to Unicode Devanagari with one font, and keep numbers as numbers and dates in one format.
- Enter or extract the rows, then run counts and spot checks back against the source.
- Apply the PDF corrections from a marked up list so every change is traceable.
- Return a short query list for anything ambiguous rather than guessing at it.

You get the corrected Excel file, the corrected PDF and the query list.

Proof: https://davespinelli.github.io/Claude-Space/

Two questions: is the Hindi source digital, scanned or handwritten, and how many rows and pages, against what deadline?
