## Proposal

UK infrastructure planning runs on constraints a generic scheduler does not know about: possession windows, consents that must land before a task starts, crews that cannot be in two places, and a programme that has to stay defensible when a date moves. Automating it is less about generating a plan than about making those constraints explicit enough that a generated plan can be trusted.

Plan:
- Write the constraint model down first with your planners: dependencies, durations, calendars, access windows, resource limits.
- Build the scheduling engine against that model, so every date it produces traces to a rule rather than to a black box.
- Use the language model where it earns its place, reading briefs into structured tasks, not choosing dates.
- Expose it as an API plus a review screen, so a planner approves or overrides before anything is published.
- Test it against a programme you have already delivered and show where it agrees and differs.

You get the engine, the API, the review screen, tests and the written constraint model.
