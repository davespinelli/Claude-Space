## Proposal

Several raw datasets is the part that decides whether this works. Files from different systems rarely agree on their keys: the customer code carries a prefix in one export and not the other, dates land as text in one and as dates in the other. A dashboard built on a join that quietly drops a third of the rows still renders and is still wrong.

Plan:
- Profile each dataset first and report row counts, key overlap and anything that will not join.
- Build the model in Power Query with the cleaning steps named, not done by hand in the files.
- Write the measures in DAX with a short definition for each, so a number on the page can be traced.
- Lay out the report around the questions you actually ask of it.
- Reconcile the headline totals back to the raw files before handover.

You get the pbix file, the measure definitions and a note on refreshing it with new extracts.

Proof: https://davespinelli.github.io/Claude-Space/ (Python built, same modelling work, different tool)

Two questions: what are the datasets and where do they come from, and which three decisions should the dashboard answer?
