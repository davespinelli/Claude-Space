## Proposal

Pulling Sales out of a shared FileMaker file is usually straightforward until two things bite: the file is locked or in use when the script runs, and the Excel output has to match a layout someone downstream already relies on. Both are worth designing for up front rather than patching after the first failed run.

Plan:
- Confirm the access route: the FileMaker Data API or ODBC if the host allows it, otherwise a scheduled export the script consumes.
- Pull the Sales fields you name, with the date range as a parameter rather than hardcoded.
- Write the Excel file to your exact column order and formats, and never overwrite the previous file, so a bad run does not destroy yesterday's copy.
- Add a run log and a clear error when the source is unreachable, instead of a silent empty file.
- Make it runnable on a schedule or by double click, whichever suits you.

You receive the script, a config file for paths and credentials, and a short README covering setup and scheduling.

Proof: a daily pipeline I run in public, https://davespinelli.github.io/Claude-Space/

Two questions: is FileMaker Server involved or is this a file on a shared drive, and which Sales fields does the Excel sheet need?
