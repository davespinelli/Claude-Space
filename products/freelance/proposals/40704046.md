## Proposal

A gateway in front of model inference lives or dies on what it does when a backend is slow, not when it is healthy. Inference calls run for seconds, so a naive proxy holds connections open, queues behind one stuck request and times out the whole pool. Streaming complicates it further: you cannot retry a request whose first tokens already reached the client.

Plan:
- Build it as FastAPI with async routing to your model backends, health checks and failover between them.
- Add API keys per tenant, per key rate limits and quotas, enforced before the request reaches a backend.
- Support streaming and non streaming responses, with request timeouts and a bounded queue instead of unbounded waiting.
- Log every call with model, latency, token counts and outcome, exposed as usage and cost per key.
- Ship with tests, a load test showing behaviour under a slow backend, Docker setup and a README.

You get the gateway, tests, deployment files and documentation.
