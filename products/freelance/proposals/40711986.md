## Proposal

JWT flows in FastAPI tend to break for a short list of reasons: the signing secret changes on restart so yesterday's tokens no longer verify, clock skew pushes exp past the boundary, refresh rotates without revoking the old token so two sessions disagree, or a dependency returns a None user with a 200 instead of a 401. Which one it is decides whether this is an hour or a day, so the first thing I do is reproduce it rather than guess.

Plan:
- Reproduce the failure locally from your steps before touching any code.
- Trace the whole path: issue, decode, the auth dependency, refresh, logout.
- Fix the actual cause, not the symptom. Widening token lifetime to make it go away is not a fix.
- Add tests that fail on the current code and pass on the fixed code, so it cannot come back quietly.
- Short write-up of what was wrong and why.

You get the patch, the tests and the note.
