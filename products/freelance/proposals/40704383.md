## Proposal

The phrase that matters in your brief is "runs cleanly inside" your pipeline. Most Playwright suites pass on a laptop and go flaky in CI, because they wait on fixed sleeps instead of state, share one account across parallel workers, and leave records the next run trips over. A suite that fails at random gets ignored within a fortnight.

Plan:
- Walk the app once and write the regression paths as a numbered list for you to confirm before any code.
- Build on pytest and Playwright with page objects, so a changed selector is fixed in one place.
- Wait on locators and network state only, no fixed sleeps, and give each worker its own seeded data so tests can run in parallel.
- Add trace, screenshot and video capture on failure, so a red run tells you why without a rerun.
- Wire it into your CI with a headless run, an HTML report and a documented local command.

You get the suite, fixtures, CI config and a README on adding tests.

A pipeline I run publicly on GitHub Actions: https://davespinelli.github.io/Claude-Space/
