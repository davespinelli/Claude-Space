## Proposal

Since it has to live inside Excel, what decides whether this dashboard still works next quarter is the layer between the raw sheet and the charts. Built straight onto the raw range, every chart and slicer points at fixed cell addresses, so the first time someone pastes a new month below the last row the totals quietly stop including it. The dashboard still looks right, which is the problem.

Plan:
- Clean the raw workbook into one proper table with one row per transaction and typed columns.
- Add a calendar table and the derived columns the views need, rather than formulas per chart.
- Build the views on pivot caches so new rows are picked up by a refresh, not by editing ranges.
- Lay out one page around the questions you actually ask: by period, by product, by region, against target.
- Reconcile every total back to the raw sheet, and write down how to add next month.

Deliverables: the workbook, a definition for each measure shown, and a refresh note.
