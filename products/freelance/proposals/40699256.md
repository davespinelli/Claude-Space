## Proposal

The phrase in your brief that decides the build is structured pages. A SharePoint dashboard built on documents and free text looks fine for a month and then cannot be filtered, because the numbers live inside attachments. Dashboards need SharePoint lists with typed columns behind them, and that is a decision to make before any page is laid out.

Plan:
- Model the data as SharePoint lists with typed columns, choice fields, and lookups, rather than uploaded workbooks.
- Build the site pages per team, with views filtered to what each team owns.
- Dashboards over those lists: status rollups, counts by owner, and overdue items, refreshing without manual work.
- Permissions set at the list level so people see their own area without separate sites.
- A short admin note on adding a column, a view, or a team later.

You get the configured site, lists, views, dashboard pages, and the admin guide.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: is this SharePoint Online with Power BI available, and where does the data live today, in Excel files or an existing system?
