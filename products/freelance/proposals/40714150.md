## Proposal

Payment posting goes wrong quietly. A remittance covers six claims, the totals get keyed as one line, and three months later the aging report says money is outstanding that already landed. The fix is not faster typing, it is making every posted line reconcile back to the deposit it came from.

Plan:
- Agree the sheet layout: one row per claim line, with payer, check or EFT reference, date, allowed, paid, adjustment and patient responsibility.
- Post the backlog you have now against that layout.
- Reconcile each remittance so posted amounts sum to the deposit, and flag any that do not instead of forcing them.
- Give you a short exception list: underpayments, denials and anything that needs your call.
- Leave a simple validation sheet so the same checks run on future batches.

You get the posted workbook, the reconciliation tab, the exception list and a one page instruction note.

Work I run in public: https://davespinelli.github.io/Claude-Space/
