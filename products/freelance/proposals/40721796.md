## Proposal

Plugging a dashboard straight into a Mongo cluster is easy for a day and painful for a month. Collections are not uniform: a field is missing on older documents, or holds a string where newer ones hold a number, and the chart shows a confident total that is quietly wrong.

Plan:
- Profile the collections first and tell you which fields are consistent enough to chart.
- Connect through a read only user, with the aggregation done in Mongo rather than pulling collections into the page.
- Build the dashboard around the few numbers you actually check daily, with the breakdowns behind them.
- Cache query results so opening the page does not hit the cluster every time.
- Deliver the code and a one command run, so it lives on your own server and not mine.

On the AI side, a question box restricted to the profiled fields turns plain English into a filter it can actually answer, rather than inventing a query.

Proof, a live dashboard I run: https://davespinelli.github.io/Claude-Space/

Two questions: which collections matter, and what are the three numbers you would check first thing in the morning? Is a read only connection string available?
