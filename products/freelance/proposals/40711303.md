## Proposal

A runner that chains several models fails at the seams. Whatever model one returns becomes instruction text for model two, so a single hostile string in an input document travels the whole chain, and a format slip at hop one turns into a parse failure at hop three. The second problem is measurement: without a frozen set of failing cases, a rewrite feels better and nobody can tell whether it fixed the failure or moved it.

Plan:
- Map the chain hop by hop and mark every point where untrusted text enters.
- Freeze a test set from your real failures, each with a pass/fail check.
- Score the current runner on it, so there is a baseline to beat.
- Harden in numbered passes: data and instructions structurally separated, output validated between hops, refusals handled rather than retried blindly.
- Rerun the suite after each pass and report the delta.

You get the test harness, the hardened prompts, the scored before and after, and notes on what still fails.
