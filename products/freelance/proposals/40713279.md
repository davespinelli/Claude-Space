## Proposal

PDFs and Word files are two different extraction problems sharing one job. Word keeps its structure, so the fields come out cleanly. PDFs either carry a text layer or they do not, and if any were scanned or printed to PDF the text has to be recovered before it can be parsed. Either way the thing that breaks a run of documents is layout drift: one form uses a table, the next uses the same labels in a paragraph, and a copy job silently loads the wrong column.

Plan:
- Sort your files into text-layer PDF, scanned PDF and Word, and handle each on its own path.
- Write a parser per document layout, keyed off the labels rather than fixed positions.
- Validate every row before load: required fields present, types correct, duplicates flagged.
- Load into your database, with the source filename and page kept on each row.
- Rerunnable script plus an exceptions file listing anything it would not load.

You get the parser, the loader, the exceptions report and the source.

Pipeline I run in public: https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many files and how many distinct layouts are in them, and which database are we loading into?
