## Proposal

Fifty-two pairs of vol surface is a data problem before a front-end problem. Each pair arrives as a grid across tenors and deltas, so the page has to decide what it recomputes on each refresh and what it caches. The failure mode that costs money is subtler: a surface that stopped updating looks exactly like one that did not move, so staleness has to be shown on screen rather than assumed.

Plan:
- Ingest from your entitled Bloomberg connection, one snapshot per pair per refresh.
- Normalise to a tenor and delta grid, with the pull time kept on every point.
- Dashboard: pair list, surface view, term structure, change against the previous snapshot.
- Staleness and gap flags, visible per pair.
- Deploy with the refresh on a schedule, plus a README.

You get the ingest layer, the dashboard, the snapshot history and the source.

Dashboard I run in public: https://davespinelli.github.io/Claude-Space/

To be straight: this band buys the ingest plus one working dashboard across the 52 pairs, not a platform.
