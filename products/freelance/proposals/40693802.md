## Proposal

One-off automation scripts usually work for a week and then break, because the manual step they replaced was quietly handling exceptions the script never saw: a renamed file, a blank field, a row that arrives twice. Your brief describes a new script rather than a fix, so the first thing to pin down is what you do when the input is wrong.

Plan:
- Walk your manual steps with you once and write them down as an explicit sequence, including the judgement calls you make.
- Build it in plain Python with common libraries only, so you can run and read it.
- Handle failures up front: bad input is logged and skipped rather than crashing the run, with a summary of what it skipped.
- Add a dry run mode so you can see what it would do before it does it.
- Test it against your real sample data, not invented data.

You receive the script, sample input and output, and a short README.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: what does the process take in and produce today, and should it run on a schedule or only when you start it?
