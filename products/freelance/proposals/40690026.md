## Proposal

A two to five sheet customer workbook rarely maps one to one onto SQL Server tables. The usual snags are types and keys: a phone number Excel has stored as a float, dates that are text on some rows, a customer that appears on two sheets with slightly different spelling, and no column that is reliably unique. Import without settling those first and you get a loaded table nobody trusts.

Plan:
- Read your workbook and write down the target schema: tables, column types, keys and the relationships between sheets.
- Agree how to match records across sheets and what counts as the same customer.
- Build the loader in Python with pyodbc, coercing types explicitly and rejecting rather than truncating bad values.
- Make it rerunnable: an insert or update by key so a corrected workbook can simply be loaded again.
- Deliver row counts and a reconciliation of workbook rows against rows in SQL Server.

You receive the loader, the schema script, the reconciliation report and a README.

Live example of a data pipeline I run: https://davespinelli.github.io/Claude-Space/

Two questions: is a Python loader acceptable or does this need to be C# to fit your stack, and do the target tables already exist?
