## Proposal

Swapping the stock LLM on an R1 EDU for a local 2B model is a memory and latency problem more than a model choice. The Jetson is already carrying perception and control, so the language model has to fit in the memory that is left and answer fast enough that the robot does not look frozen while it thinks.

Plan:
- Measure free memory and load on the Jetson while your current stack is running, before choosing a build.
- Build the 2B model as a quantised local engine, llama.cpp or TensorRT-LLM, and benchmark first-token latency on the board itself.
- Put it behind the same interface the stock LLM exposes, so nothing downstream has to change.
- Add a timeout fallback, so a slow generation degrades to a short canned reply instead of stalling the robot.

You receive the build scripts, the service definition, a benchmark table and a README covering a reflash.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
