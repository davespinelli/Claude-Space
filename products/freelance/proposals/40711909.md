## Proposal

SP-API work rarely breaks on the endpoints. It breaks on the parts around them: LWA tokens expiring mid-run, per-operation rate budgets that throttle a bulk pull halfway, reports that are requested now and ready later, and the restricted-data token flow if any buyer information is in scope. A desktop tool that ignores those looks fine for a week and then silently returns stale numbers.

Plan:
- Confirm which SP-API operations and roles your workflow actually needs, and whether restricted data is involved.
- Build the auth and throttling layer: token refresh, per-endpoint rate budgets, retry with backoff.
- Handle reports asynchronously, cache results locally, and make a failed run resume rather than restart.
- Wrap it in the desktop app with a plain window for run, status and errors.
- Log every call and response so any disagreement with Seller Central can be traced afterwards.

You get the app, the source, and a runbook covering credentials and failure recovery.
