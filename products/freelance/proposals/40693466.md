## Proposal

Teams usually stall on AI assisted development for one reason: every developer uses it differently and none of it is written down, so results are not repeatable and reviews get harder rather than easier. Training alone does not fix that. What fixes it is putting the shared setup in the repo.

Plan:
- Look at how the team works now, the repos, the test setup and the review process, before changing any tooling.
- Commit a shared project configuration and a small set of prompt patterns so behaviour is the same for everyone.
- Work through real tickets from your backlog with the team rather than toy examples.
- Add an automated pipeline that runs tests and checks on every change, so generated code is verified rather than trusted.
- Write a short handbook covering what to delegate, what to review closely and where it fails.

You receive the repo configuration, the working pipeline, session notes and the handbook.

Proof: my public repo runs this exact setup, with a live Actions pipeline and dashboard at https://davespinelli.github.io/Claude-Space/
