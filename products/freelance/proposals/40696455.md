## Proposal

A daily transfer job like this rarely fails on the typing. It fails on the day one record gets submitted twice because nobody tracked what was already sent, or a field the portal rejects stops the run. So the useful deliverable is not the entry alone, it is a record of exactly which items went in and which did not.

Plan:
- Set up one source sheet with the fields the portal needs, so each day's records arrive in a known shape.
- Validate before submitting: required fields present, dates and numbers in the portal's format, duplicates flagged against what was already sent.
- Submit each record and write back a status and timestamp, so nothing is entered twice or silently missed.
- Send a short daily summary: submitted, skipped, and the reason for each skip.
- Run the first days alongside your current process so we can compare before you rely on it.

You receive the working daily process, the tracking sheet and a runbook.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many records a day, and does the portal have an upload or API option, or is it form entry only?
