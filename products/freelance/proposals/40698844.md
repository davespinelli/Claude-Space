## Proposal

Extensions that scrape text break for two reasons: the page renders its content after load, so a script that runs too early sees an empty container, and the class names it targets change on the next site update. Both are avoidable, but only if the selectors live in settings rather than hard coded in the extension.

Plan:
- Build a Manifest V3 extension with a content script that waits for the target element instead of assuming it exists.
- Keep the selectors in an options page, so a site change is a settings edit and not a rebuild.
- Extract to a clean structure, with whitespace and duplicates handled, and export to CSV or JSON.
- Handle paginated and scrolling pages with a stop condition, at a pace that stays polite to the site.
- Log what was captured and what was skipped, so an empty result is explained.

You receive the unpacked extension, the source, and a note on loading it and adding a new site.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
