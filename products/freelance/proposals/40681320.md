## Proposal

Your stack list (XGBoost, Isolation Forest, SHAP, FastAPI) says you want more than a score. You want a fraud decision you can explain to a risk team, and an endpoint that returns it fast.

Plan:
- Profile the transaction data and build time based train/test splits, so the model is scored the way it will actually run and no future information leaks in.
- Train two lines of defence: XGBoost on labelled fraud, Isolation Forest for unlabelled anomalies, blended into one risk score.
- Tune the threshold against your real cost of a false positive versus a missed fraud, not just AUC.
- Wrap it in FastAPI with a scoring endpoint, per transaction SHAP reasons, and request logging to SQL.
- Ship tests, a README, and a short report with the confusion matrix and precision at your alert budget.

You receive the repo, the trained model artefacts, the API and the report.

Public example of my Python pipeline with tests on GitHub Actions: https://github.com/davespinelli/Claude-Space

Two questions: do you have labelled fraud cases, and roughly how many rows? Real time scoring or nightly batch?
