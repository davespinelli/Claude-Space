## Proposal

PDF forms split into two cases and the price of the job depends entirely on which one you have. If the form has real AcroForm fields, the values can be read straight out by field name and the extraction is exact. If it was printed and scanned, or flattened on save, the fields are gone and the values have to be located by position and read with OCR, which needs a verification pass. I check that first and tell you which case you are in.

Plan:
- Test a sample file for live form fields, and report which case applies before building anything.
- Map field names to your Excel column headers through a config, so a form revision does not break the tool.
- Extract to one row per form, with the source filename kept on every row.
- Flag empty required fields and values that do not match their expected type rather than writing them silently.
- Deliver a script you can rerun on the next batch of files.

You receive the Excel output, the exceptions tab, the script and a README.
