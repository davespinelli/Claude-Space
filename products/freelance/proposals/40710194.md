## Proposal

The question that decides whether an RPA build lasts is whether the target has anything behind the screen. A bot that clicks through a user interface breaks the week that interface changes, and it usually breaks silently. Where an API, a command line or a file drop exists, the bot should use it and keep the clicking path only as a fallback, so I would want to establish that first.

Plan:
- Confirm the target application and whether an API, CLI or file interface exists behind it.
- Build against the most stable interface available, driving the screen only where there is no alternative.
- Make every step idempotent and restart-safe, so a half-finished run can be repeated without duplicating work.
- Capture logs and a screenshot on failure, because a silent RPA failure costs more than a loud one.
- Schedule it and hand over a runbook for the day the target does change.

You get the bot, the source, the schedule and the runbook.
