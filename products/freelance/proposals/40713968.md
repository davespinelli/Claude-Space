## Proposal

Letting a model drive a Windows desktop works fine in a demo and fails in week two, because a dialog moves, a click lands somewhere unintended, and there is no record of what it did. The part worth paying for is the boundary: what it is allowed to touch, and what gets logged.

Plan:
- List the two or three tasks you want running first, with the exact start and finish state of each.
- Wire Claude to the machine through tools you control, preferring file, API and command line paths over clicking where one exists.
- Put guardrails around it: an allowed action list, no writes outside named folders, and a confirm step before anything destructive.
- Log every step to a file so a bad run can be read back rather than guessed at.
- Run each task supervised for a few days, then hand over a runbook.

You get the working setup, the tool definitions, the guardrail config, the logs and the runbook.

Automation I run in public: https://davespinelli.github.io/Claude-Space/
