## Proposal

Mixed text and numerical content is where PDF to sheet transfers usually go wrong. Copy and paste turns numbers into text, so the sheet will not sum, and any figure written in brackets or with a currency symbol stops being a number at all. That is worth getting right the first time.

Plan:
- Extract the text layer per page with pdfplumber, keeping the reading order intact.
- Split text and numeric fields into their own columns, with numbers stored as numbers.
- Standardise dates and currency so the sheet sorts and totals correctly.
- Spot check a sample of rows against the source pages and record the check.
- Deliver into Google Sheets, formatted, with the source file and page noted per row.

You receive the populated sheet plus the extraction script, so the next batch of PDFs is a rerun rather than a new job.

Example of my public Python automation with tests: https://github.com/davespinelli/Claude-Space

Two questions: how many PDFs and roughly how many pages each, and should each file be its own tab or all rows in one sheet?
