## Proposal

Running two businesses through one assistant makes separation the first real design decision, before any tool is wired up. If the two sides share one set of tools, a vague question pulls the wrong company records into an answer, and you will not notice until it is wrong in a way that matters.

Plan:
- Start read only. The assistant answers questions from your data before it is allowed to change anything.
- One MCP server per system you actually use, with tools named after your operations rather than after the API underneath.
- Keep the two businesses separated at the tool layer, so a query scoped to one cannot reach the other's records.
- Add write actions one at a time, each with a confirmation step and a log of exactly what it did.
- Ship a runbook so you can add a tool later without paying me to do it.

Deliverables: the MCP server code, config, action logs, and the runbook.

Proof: my public pipeline, dashboard and automation at https://davespinelli.github.io/Claude-Space/

Two questions: which systems hold the data today, and which single task costs you the most time each week?
