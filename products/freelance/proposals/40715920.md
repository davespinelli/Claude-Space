## Proposal

Mixed text and numeric records fail in a way that hides itself. A column holding 1,240, "1240 units" and "approx 1.2k" sums to whatever Excel can read and silently drops the rest, so the total looks plausible and is wrong. Ordering a backlog like that is mostly deciding what each messy value was meant to say, and recording the cases where that cannot be decided.

Plan:
- Take one sample of the backlog first and write down the actual patterns present, rather than assuming them.
- Agree one rule per pattern with you, including how units, ranges and blanks should read.
- Apply the rules in a repeatable script, so a second batch next month costs you nothing to clean.
- Keep the original value beside the cleaned one, so every change stays auditable.
- Return the rows that no rule could resolve as a separate list instead of guessing.

You receive the cleaned file, the original values alongside, the rules document, the script, and the exceptions list.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/

Two questions: roughly how many records and in what format, and is this a one-off backlog or something arriving weekly?
