## Proposal

Form filling apps rarely fail at extraction. They fail at the field the model was unsure about, because a filled form looks finished whether or not it is right. Nothing on the page says a date was a guess, so the person checking has no reason to look twice. That is the difference between a tool staff trust and one they redo by hand.

Plan:
- Define the document set and field schema first, so every field has a type, a required flag and a validation rule.
- Extract field by field with a confidence score and the source span, never one output blob with no provenance.
- Build a review screen that puts the filled form beside the source document and highlights low confidence fields.
- Render back into the real file, keeping the original layout, and version every generated document.
- Stage the build: one document type end to end first, then the rest, so you see it working before the full spend.

Deliverables: the application, the schema config, the reviewer workflow and deployment notes.
