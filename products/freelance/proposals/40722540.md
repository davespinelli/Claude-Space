## Proposal

Moving several spreadsheets into a database almost always breaks in the same place: the column that looks numeric. In a sheet one column can hold 1,250, a blank, an "N/A" and a footnote, and nothing complains. A table allows one type per column, so it either refuses to load or lands quietly as text and stops adding up. The second break is the workbooks disagreeing: the same field under a different heading, or a column added partway through.

Plan:
- Profile every workbook first and send you one table of columns, detected types and the odd values found.
- Agree one target schema with keys, and decide up front what happens to rows that do not fit.
- Load with a script rather than by hand, so the next batch is a re-run.
- Reconcile after loading: row counts per sheet and a total for every numeric column, sheet against table.
- Return rejected rows in a file with the reason attached, rather than dropping them.

Deliverables: the loaded database, the load script, a schema note and the reject file.
