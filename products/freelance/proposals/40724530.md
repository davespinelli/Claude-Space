## Proposal

For a Bank Nifty options bot the rules are not the hard part. The hard part is that an options rule is not an order. Which strike, which expiry, what to do when the strike has no depth, and how the position is handled at expiry are decisions your code makes for you every session. If they are not written down, the bot trades something other than the idea you tested.

Plan:
- Write the strike, expiry and roll rules down explicitly, including what happens when the quote is wide or missing.
- Signal module off the broker feed, with the same logic runnable over stored data so results are checkable.
- Order layer with one client order id per signal and reconciliation against broker positions on every start.
- Hard caps: lots per trade, open exposure, daily loss, plus a square-off time that runs regardless of signal.
- Run it on the cloud with a daily log, and keep the GUI a view over that log rather than the holder of state.

Deliverables: the Python bot, the rules document, the deployment, and a runbook.

Proof: https://davespinelli.github.io/Claude-Space/ (public backtest engine and broker execution bot)
