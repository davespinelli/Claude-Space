## Proposal

Calling the API is the easy part. The problem with resume screening is that the same CV asked twice can come back with a different verdict, and a hiring decision has to survive someone asking why that candidate was dropped. So the screen needs fixed criteria, a score recorded per criterion, and the line of the resume each score came from.

Plan:
- Turn your job description into a scored rubric instead of asking the model for one overall verdict.
- Parse every resume to plain text first, PDF and DOCX both, so the model sees comparable input each time.
- Score each criterion separately with the supporting text quoted, and save the result against the candidate.
- Rank and shortlist rather than auto reject. The app hands you an ordered list with reasons you can read.
- Keep a log of every screen so a decision can be traced back months later.

You get the web app, the rubric configuration, the stored score history, and deployment notes.

A pipeline I run publicly on GitHub Actions: https://davespinelli.github.io/Claude-Space/
