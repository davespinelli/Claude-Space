## Proposal

When figures move out of a working workbook daily, the two copies drift the moment you edit a past row. That day's transfer looks fine, the destination still holds the old number, and the gap shows up when someone questions a month total.

Plan:
- Agree the destination and the exact fields, so one transaction becomes one row with the same date and category on both sides.
- Give each row a key, so a re sent day updates the entry already there instead of adding a second one.
- Run one fixed daily cycle: you post the day's rows, I return the updated destination the same day with a running total that must match.
- Keep a queries list for anything I cannot categorise confidently, rather than guessing.
- Where the destination allows an import or an API, script the transfer so a refresh is a rerun and not a retype.

You get the updated destination each day, a daily match check, the queries list and a note on how the transfer runs.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/

Two questions: where do the figures land, another sheet or an accounting package, and roughly how many transactions a day?
