## Proposal

You have already done the hard part, consolidating the scattered sheets into one hub with live pipelines feeding it. That changes what the automation has to be careful about. Writing payment status into a hub that a pipeline is also refreshing means the two can land on the same rows and one quietly overwrites the other. The status updates need to key on an invoice or reference id and write only their own columns, never a whole row.

Plan:
- Map where payment status comes from now and which column in the hub it lands in.
- Match on a stable id, so a re-sorted or re-imported sheet still updates the right record.
- Write only the status columns, leaving everything the pipelines own untouched.
- Log each run: rows matched, rows updated, and any reference it could not find.
- Set it on a schedule and leave a short note on how to pause or re-run it.

Deliverables: the automation, the run log, and the setup note.
