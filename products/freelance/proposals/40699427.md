## Proposal

Gauging market risk automatically is the easy half. The hard half is that a risk number computed from a live data feed changes every time you load the page, so users cannot tell whether the market moved or your code did. That is what makes people stop trusting these tools.

Plan:
- Pull prices once per day on a schedule, store them, and compute risk from the stored history rather than from a live call at page load.
- Compute the measures explicitly: rolling volatility, drawdown from peak, and correlation against a chosen benchmark, each with the window written on screen.
- Serve them through a small FastAPI backend so the front end never talks to the data vendor directly.
- Front end shows the current reading, its history, and what changed since yesterday.
- Snapshot every daily run so any past number can be reproduced.

You get the app, the scheduled pipeline, tests, and deployment notes.

Proof: my daily pipeline and dashboard run publicly at https://davespinelli.github.io/Claude-Space/
