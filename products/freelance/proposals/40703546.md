## Proposal

Inventory and demand data is awkward to present because the two move on different clocks. Stock is a level you read at a point in time, demand is a rate over a period, and putting them on one chart without saying which is which is how a dashboard ends up looking busy while answering nothing.

Plan:
- Agree the three or four questions the page has to answer, then design the layout around those rather than around chart types.
- Build the frontend in React with a small component set: KPI row, trend chart, breakdown table, filter bar.
- Wire it to your data source or to a mock API with the same shape, so the swap later is a one-line change.
- Make it read properly on a phone, and keep loading and empty states visible instead of blank panels.
- Ship with a build step and a deploy that runs from a repo, not from my machine.

You get the source, the component set, a deployed build and a short README.
