## Proposal

You picked SQLModel rather than raw SQLAlchemy, which tells me you want one set of models serving both the database and the API schema. That choice pays off only if migrations are wired in from day one. Most FastAPI projects skip Alembic early, and by the third schema change the team is dropping and recreating tables, which is fatal once real financial records are in there.

Plan:
- FastAPI app with SQLModel entities, Alembic migrations, and Pydantic response models kept separate from table models.
- Auth with hashed passwords, JWT sessions, and role checks enforced at the dependency layer, not in each route.
- Money as integer minor units with an explicit currency field, never floats.
- React front end against a generated OpenAPI client, so the types cannot drift from the backend.
- Pytest suite over the API plus a GitHub Actions run on every push.

You get the repo, migrations, tests, a seeded dev database, and a deploy runbook.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
