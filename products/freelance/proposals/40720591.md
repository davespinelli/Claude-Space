## Proposal

Building the server first is the right call, and what decides whether it holds up is how the AI calls are shaped. A model call takes seconds, sometimes fails, and occasionally returns something that does not parse. Wire it straight into a request and the front end sits there spinning, the browser times out, and the user retries, which sends the same work through again and bills you twice.

Plan:
- Agree the API contract first, endpoints, request and response schemas, so the SPA can be built against it.
- Implement in FastAPI with Pydantic models, so every payload is validated at the edge.
- Run model calls as background jobs with a status endpoint, plus retries, timeouts and an idempotency key per request.
- Validate model output against a schema before it is stored or returned, never pass raw text through.
- Ship with auth, request logging and tests on the endpoints.

You get the service, the OpenAPI spec the front end can generate a client from, tests and deployment notes.
