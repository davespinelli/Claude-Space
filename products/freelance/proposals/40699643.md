## Proposal

Nested tables are where the generic PDF converters give up. They flatten a two or three level header into one row, so a number that belonged under a parent column loses the label that gave it meaning, and the spreadsheet looks complete while being wrong.

Plan:
- Extract with a table aware parser rather than plain text, so column boundaries survive the conversion.
- Rebuild the nested headers into one flat header row, one column per leaf, carrying the parent label in the column name.
- Keep numbers as numbers: brackets read as negatives, separators removed, footnote markers stripped and recorded separately.
- Check every row and column total against the totals the PDF itself prints, and report any cell that does not agree.
- Hand over the extraction script as well as the workbook, so another file in the same layout is a rerun.

You get the Excel workbook, one sheet per source table, the totals check and the script.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
