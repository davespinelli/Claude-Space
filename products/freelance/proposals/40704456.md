## Proposal

Your brief asks for two things that work differently. Segmentation has no right answer to check against, so the only honest test is whether the groups survive resampling and differ on something you care about. Prediction needs a named outcome to learn from, such as churn in the next ninety days. Without that column, a model can only be graded on how well it reproduces its own labels, which always looks excellent and means nothing.

Plan:
- Profile the raw data first and report what is populated, since sparse fields decide the feature set.
- Build recency, frequency and value features, plus whatever behaviour the data supports.
- Cluster with k-means and a Gaussian mixture, choosing the group count on stability, not a chart.
- Describe each segment in business terms: size, spend, tenure, and what makes it different.
- If an outcome column exists, add a classifier scored on a held-out period, not a random split.

You get the notebook, the segment profiles, a scoring script for new customers, and a short report.

A pipeline I run publicly on GitHub Actions: https://davespinelli.github.io/Claude-Space/

Two questions: what decision will the segments drive, and is there an outcome column to predict?
