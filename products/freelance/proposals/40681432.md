## Proposal

Most reporting projects fail at the ETL, not the dashboard. Sales and operations data arriving in a slightly different shape each month is what turns a Power BI report back into a manual weekly chore.

Plan:
- Map every source (ERP, CRM, spreadsheets, databases) and agree one canonical schema for sales, orders and operations.
- Build a Python ETL that ingests, validates and loads on a schedule, with row counts and reconciliation checks that fail loudly when a feed breaks.
- Model a facts and dimensions layer so the Power BI measures stay simple and stay correct.
- Build the dashboard: revenue, margin and operations KPIs, drill through by region and product, plus an AI written summary of what moved and why.
- Hand over a runbook, tests and a scheduled refresh you can run without me.

You receive the ETL repo, the warehouse schema, the report file and documentation.

Live example of a scheduled pipeline I run: https://davespinelli.github.io/Claude-Space/

Two questions: which systems hold the source data today, and is Power BI fixed or would a hosted web dashboard also work?
