## Proposal

Ongoing processing work usually goes wrong at the handover rather than in the work itself. The rules live in someone's head, so the first batch comes back right, and by the fifth it has quietly drifted because a new edge case got decided differently. The fix is writing the rules down while doing the first batch, not afterwards.

Plan:
- Do the first batch with you available, and record each decision rule as the case comes up.
- Return a fixed output layout so every batch is comparable to the last one.
- Put rows I could not decide in a separate tab with the reason, rather than guessing at them.
- Script the repetitive steps once the rules settle, which cuts turnaround and cost per batch from there on.
- Report the same three figures with each batch: rows in, rows out, rows flagged.

You get the processed files, the written rules, and the flagged rows. This price covers the first defined batch, and the same rate continues from there.
