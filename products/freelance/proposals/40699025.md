## Proposal

CRM migrations rarely fail on the upload. They fail on duplicates, because the same customer exists twice in the old system under two spellings, and on history, because emails import without linking to the contact they belong to. You end up with a populated CRM that nobody trusts as the single source.

Plan:
- Profile the export first and report duplicate counts and missing fields, before anything is loaded.
- Agree a match key, then merge duplicates with a log showing which records were combined and why.
- Load contacts, companies and deals through the Bitrix24 REST API, in that order, so relations resolve.
- Import the mail history attached to the matching contact, keeping original dates and direction.
- Run it into a test portal first, review the result together, then load production once.

You receive the import scripts, the duplicate and error logs, and a re-runnable process for later batches.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
