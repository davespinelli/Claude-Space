## Proposal

The risk in extracting fields from incoming email is not the model failing loudly, it is the model being confidently wrong on one order in fifty and that value going straight into your system. A workflow that removes the typing has to make its uncertainty visible, or you have replaced data entry with data checking.

Plan:
- Pull mail through the mailbox API, keep the message id, and never process the same message twice.
- Extract the fields with a schema the model must fill, so missing values come back empty rather than invented.
- Score each field, auto-post the confident ones and route the rest to a short review queue.
- Write into your destination system through its API, with a rollback log of what was written.
- Run it on a schedule with alerting, so a broken sender template is caught the same day.

You receive the workflow, the review queue, the logs, and a runbook.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
