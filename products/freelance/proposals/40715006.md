## Proposal

A spreadsheet database that has to stay current usually fails the same way. Updates arrive faster than anyone can key them, it slips a week behind, and after that nobody trusts it enough to use it. The way out is to let the repeating updates load themselves and keep hand entry for the genuine exceptions.

Plan:
- Look at where updates actually arrive from now, forms, email, exports, and pick the ones that repeat.
- Build a loader that appends or updates rows from those sources, matching on a key so nothing duplicates.
- Add validation in the sheet: required fields, allowed values, dates that have to be real.
- Run one catch-up pass so the database starts current rather than behind.
- Leave a short guide so you or anyone else can run it.

You receive the loader, the validation rules built into the sheet, the caught-up database and the guide. Straight about the budget: this buys the tooling and one catch-up pass, not an ongoing daily seat.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/
