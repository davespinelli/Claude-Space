## Proposal

Hand exporting from GLPI goes wrong in a particular way. The filter set gets rebuilt from memory each time, so two people produce two different asset counts from the same instance and nobody can say which one is right. Pinning the query in code fixes that before it fixes the typing time.

Plan:
- Agree the exact GLPI views you export today and the columns each one has to produce.
- Pull them through the GLPI REST API with a read only app token, dropping to a direct read query only for fields the API does not expose.
- Write one workbook, one sheet per view, with column formats and widths reapplied on every run.
- Add a checks sheet: row counts, last update timestamp, and any asset missing a required field.
- Schedule it on your server or a hosted runner, with the file emailed or dropped on a share when it completes.

You receive the Python job, the workbook, the run log and a README.

Proof: my public repo and live dashboard at https://davespinelli.github.io/Claude-Space/

Two questions: which GLPI version are you on and can you issue an API token, and how often should the file rebuild?
