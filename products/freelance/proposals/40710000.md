## Proposal

A workout PDF is a layout problem before it is a data problem. Programs print as week blocks with exercise, sets, reps, load and rest packed into one visual row, and the useful spreadsheet is the opposite shape: one row per set, with week and day as columns you can filter on. Converted as it looks on the page, it prints nicely and cannot be sorted.

Plan:
- Check whether the PDF carries a real text layer or is a scan, and tell you which before any work starts.
- Agree the target shape with you: one row per exercise per day, or one row per set.
- Extract the program into that shape, keeping week, day, exercise, sets, reps, load and rest as separate columns.
- Read every page back against the original and flag anything the PDF states ambiguously.
- Add filters and a per-week summary so the sheet is usable, not just populated.

You get the XLSX, a note of anything ambiguous, and the extraction script if the format repeats.

Work I run in public: https://davespinelli.github.io/Claude-Space/

Two questions: how many pages, and do you want one row per set or one row per exercise per day?
