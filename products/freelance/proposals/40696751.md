## Proposal

Agentic systems that work in a demo fail in production for an unglamorous reason: there is no durable record of what the agent did. A tool call times out, the run is retried, and the same side effect happens twice, with nothing in the logs to prove it. Run history has to be a first class part of the data model.

Plan:
- Start with one scoped piece rather than the whole platform, so you can judge the work before committing further.
- Model runs, steps and tool calls explicitly in the database, with inputs, outputs and status.
- Make tool calls idempotent and retryable, so a timeout costs latency rather than a duplicated action.
- Put limits at the boundary: token and cost ceilings per run, timeouts, and a hard stop on runaway loops.
- Add tests against recorded traces, so behaviour changes show up in CI rather than production.

You receive working code, tests, a schema and a short architecture note.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
