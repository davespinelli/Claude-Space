## Proposal

Most Azure and Python generative AI work arrives at the same point. A prototype answers well in a notebook, and then it has to face real documents, real users and a cost line. What closes that gap is retrieval quality, an evaluation you trust, and knowing when the model is wrong. Almost none of it is the model call itself.

Plan:
- Start with one defined slice instead of the whole system: one use case, one data source, one measurable output.
- Build retrieval properly on Azure AI Search or your existing index, with chunking and metadata that match how people actually ask.
- Put an evaluation set in place early, so a prompt or model change can be shown to help rather than assumed to.
- Add the production parts that get skipped: structured logging of prompts and responses, cost per request, and a fallback when a call fails.
- Keep it in plain Python you own, deployable through your existing Azure setup.

Deliverables: the working slice, the evaluation set with its scores, and the source with a README.
