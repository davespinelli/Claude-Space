## Proposal

Adding modules to an assistant that already works is a different job from building one. The risk is not the new module, it is the answers you already trust getting quietly worse once new content sits in the same index and starts competing for the same questions. That regression is easy to ship and hard to notice.

Plan:
- Read the current codebase and write down how a question reaches an answer today, before changing anything.
- Build each new module behind its own content source, so one module can be turned off without touching the rest.
- Keep a small set of known questions and expected answers, and run it before and after each module lands.
- Add logging on which module answered, so you can see where the assistant is actually being used.
- Hand back a short note on what I would fix next in the existing code.

You receive the new modules, the regression question set, and the deployment steps.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
