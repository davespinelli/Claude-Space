## Proposal

Handing routine execution to code is the easy half. The half that decides whether you keep it running is reconciliation: knowing each morning that the positions the system believes it holds are the ones the broker actually holds, and that no order went twice after a restart. A bot without that is one timeout away from a position nobody is watching.

Plan:
- Write your rules as an explicit signal module, then backtest on daily bars with realistic costs and no look-ahead, so you see the record before money moves.
- Run the robustness checks, sample halves and walk-forward, and tell you plainly if the edge does not hold.
- Build the order manager on Alpaca with position and exposure caps, and idempotent order ids so a restart cannot duplicate.
- Run it on paper for a week with a daily reconciliation report against the broker's own positions.
- Schedule it so it runs without your machine, logging every decision and fill.

You receive the backtest report, the source, the runbook, and the live-ready bot in two milestones, paper first.

Proof: my public repo, engine and live dashboard at https://davespinelli.github.io/Claude-Space/
