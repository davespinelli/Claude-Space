## Proposal

Post-training evaluation goes wrong in a specific way: the eval set becomes the thing being optimised, so the score moves while the model does not get better. At a few hundred prompts a two point gain is usually noise, and any prompt that leaked into the tuning data makes the number meaningless.

Plan:
- Check the tuning data for overlap with the eval prompts before reporting anything.
- Score the tuned checkpoint against the base pairwise on the same prompts, not as two separate averages.
- Put confidence intervals on every number, so you can see which differences are real at your sample size.
- Where a judge model grades, calibrate it against a hand graded set and report the agreement rate.
- Report regressions per capability slice, not only the headline gain.

You receive the evaluation harness, the slice definitions, per-slice results with intervals, and a written read on what the run does and does not show.

Proof: my public repo and live pipeline at https://davespinelli.github.io/Claude-Space/
