## Proposal

With a Scrapfly integration, the breakages are usually not in the request layer. The target markup shifts, a selector returns nothing, and the Flask app has no way to tell an honestly empty page from a parser that has quietly stopped working. That is why these apps look fine until someone checks the data.

Plan:
- Reproduce each failing case first and record what the response actually contained, so we fix causes rather than symptoms.
- Separate fetching from parsing, so a Scrapfly error, a blocked page and an empty result are three distinct outcomes with three distinct handlers.
- Add validation on every extracted record, with a run rejected when the field fill rate drops below what you expect.
- Add retries with backoff and a per run log of cost, pages fetched and records kept.
- Cover the parsers with tests against saved sample pages so future markup changes fail loudly.
