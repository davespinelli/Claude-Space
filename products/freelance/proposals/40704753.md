## Proposal

JSON to XML looks like a one line conversion until the target schema turns up. XML cares about things JSON does not: attribute versus element, required order, namespaces, empty versus missing, and how a date or a decimal must be formatted. If the receiving system validates against an XSD, a feed that is almost right is rejected in full, which is why a converter that works on your machine still fails in production.

Plan:
- Validate the output against your XSD or a sample the receiving system already accepts, and treat that as the definition of done.
- Map field by field, with explicit rules for nulls, empty lists, dates and decimals.
- Fix the scraper so the JSON it produces is complete before conversion, with a row count check on each run.
- Fail loudly on validation errors instead of sending a partial file.
- Deliver as a script you can run on a schedule, with a README and the source.
