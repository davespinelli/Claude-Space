## Proposal

Most FastAPI bugs that survive a first look are the same three: a sync call blocking the event loop so latency spikes under load, a database session shared across requests, or a dependency that swallows an exception and returns a 200 with nothing in it. All three look intermittent from the outside, which is why they are still open.

Plan:
- Reproduce each bug locally from your repo before changing anything, and say plainly if one will not reproduce.
- Fix the cause rather than the symptom, with a short note on what was actually wrong.
- Add a regression test per bug so the same fault fails loudly next time.
- Check the neighbouring routes for the same pattern, since these faults rarely appear once.
- Deliver as small reviewable commits, not one large rewrite.

You get the fixes, the tests, the commits and a written summary of each root cause.
